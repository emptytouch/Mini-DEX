## 5. 准备两个地址

作业要求「**两个不同地址**完成成交」。用你钱包里的两个 MetaMask 账户：

1. **账户 A** = 你原来那个（`0xA0b760DC…`）。它已经在交易所里有余额了（昨天 demo 充的
   500 USDC / 5 WAVAX，后端启动时会从链上回放出来）。
2. **账户 B** = 在 MetaMask 里点「创建新账户」，记下它的地址。

**给账户 B 一点 AVAX 付 gas**（mint / 充值 / 提现都要 gas）：

- 在 MetaMask 里切到账户 A → 发送 → 粘贴账户 B 的地址 → 发 **0.05 AVAX**。

**给账户 B 领测试代币**：切到账户 B，在网页左下「资产与充提」Tab 的**水龙头**卡片里点：

- `mint 1000 USDC`
- `mint 10 WAVAX`

每次都会弹 MetaMask 让你确认，确认即可。

> MetaMask 没弹窗或提示网络不对时，看顶栏有没有 `Switch to Avalanche Fuji` 按钮，点一下。

## 8. 截图⑤：两个地址完成成交

这里要**一个人分饰两角**，用 A 挂单、B 吃单。

**📸 截图要点**：一张图里同时能看到「最近成交」里那条成交记录、以及订单簿。

## 10. 截图⑦：WebSocket 私有 orders 频道（进阶 4.5）

要证明的是「**挂单推送只发给本人，别人的连接收不到**」。最直观的拍法是开两个浏览器窗口、
分别登录两个不同账户，同一个「当前委托」Tab 里各看各的。

1. 窗口一（普通窗口）登录**账户 A**，下单面板挂一张**限价卖单**（价格填远一点的，比如 `20`，数量 `1`）。
2. 窗口二（**无痕窗口**，这样 MetaMask 能切成另一个账户）登录**账户 B**。
   > 用无痕窗口是因为 MetaMask 一个浏览器配置文件只能连一个账户；两个窗口各装/各连一个账户最省事。
   > 懒得搞两个窗口的话，这一步跳过也行，直接看下面那条更方便的验证。
3. 两个窗口都点开下方的「**当前委托**」Tab。

**📸 截图要点**：**两个窗口同框** —— 窗口一有 A 的那张挂单，窗口二（B）显示「没有挂单」。
这就是私有频道：同一时刻、同一个后端，B 看不到 A 的委托。

> **更省事的替代验证**（不用两个窗口）：在窗口一挂单/撤单，看「当前委托」**立刻**变化、没有 3 秒延迟 ——
> 说明它是被推送驱动的，而不是轮询。截图时把挂单前后两张拼一起即可。

3. 刷新浏览器 <http://localhost:5173>。订单簿应该立刻被填满，右上角出现「**流动性镜像 Binance**」的标记。

4. 打开**终端 D**（或任意空终端），跑对比脚本，证明本所盘口确实等于 Binance 的盘口：

   ```bash
   cd /d/Web3/openbuild/Lesson7/Mini-DEX/server
   node scripts/mm-compare.mjs
   ```

   输出长这样（逐档价格必须完全一致）：

   ```
   后端 http://localhost:8787  mode=chain  marketMaker=0x...
   第 1 次抓取：0/3 档一致，最大价差 0.0040
   第 2 次抓取：3/3 档一致，最大价差 0.0000

   交易对 AVAXUSDT  取前 3 档（价格单位 USDC）

   ┌─────────┬──────┬────────────────────────┬────────────────────────┬──────┐
   │ (index) │ 档位 │ 本所买 / Binance买     │ 本所卖 / Binance卖     │ 一致 │
   ├─────────┼──────┼────────────────────────┼────────────────────────┼──────┤
   │ 0       │ 1    │ '11.225 / 11.22500000' │ '11.226 / 11.22600000' │ '✅' │
   │ 1       │ 2    │ '11.224 / 11.22400000' │ '11.227 / 11.22700000' │ '✅' │
   │ 2       │ 3    │ '11.223 / 11.22300000' │ '11.228 / 11.22800000' │ '✅' │
   └─────────┴──────┴────────────────────────┴────────────────────────┴──────┘
   逐档价格完全一致 ✅（第 2 次抓取，对齐在做市刚刷新之后的瞬间）
   ```

   > **脚本会反复抓几次，属正常**。本所盘口是"每 2 秒镜像一次"的**快照**，不是实时转发：
   > 脚本问的是 Binance **此刻**的盘口，两边天然差最多一个刷新间隔。行情在动的时候，
   > 第 1 次往往对不上（会打印最大价差，比如 0.0040 ≈ 两个 tick）。脚本会等本所刚刷新的那一瞬间

   >
   > 价格写法不同是正常的：本所去掉尾随 0（`11.22`），Binance 固定 8 位小数（`11.22000000`），
   > 是同一个价，脚本按数值比。
   >
   > 如果跑了 25 次仍然全 ❌：先确认「当前委托」里没有你自己遗留的挂单（有就先撤掉，否则会混进本所盘口）；
   > 行情单边快走时可能一直碰不上走平的瞬间，把 `server/.env` 里 `MM_INTERVAL_MS` 调小（如 `500`）再重启后端，
   > 快照更新鲜、更容易对上。

**📸 截图要点**：一张图里同时有**浏览器订单簿的 3 档买卖**和**终端里 `逐档价格完全一致 ✅`** 的对比表。

## 13. 截图⑩：IOC / FOK 订单（进阶 4.3）

做市开着正好有流动性可以"吃"，这一节不用第二个账户。

在**账户 A** 下，下单面板现在多了一行有效期 `GTC / IOC / FOK`。**同样一笔单，只换有效期，做三次对比**：

**① GTC（对照）** —— 买入 + 限价 + `GTC`，价格填**比卖一低很多**（比如 `5`），数量 `1`，下单。

- 结果：`未成交；剩余 1.0000 已挂单`，「当前委托」里多了一张单。**记下这个行为，下面两个跟它不一样。**

**② FOK** —— 改选 `FOK`，数量改成**明显超过簿上总量**（比如 `9999`），下单。

- 结果：`未成交（FOK 没吃到能满足条件的流动性，整单作废）`，**「当前委托」里没有新单** —— 这就是 FOK 的「要么全成，要么整单不动」。

**③ IOC** —— 改选 `IOC`，价格填**高于卖一**（页面上点「参考价」自动填就行），数量填一个**大于卖一档挂单量**的数（比如 `200`），下单。

- 结果：`成交 N 笔，均价 …；剩余 … 按 IOC 作废，未挂单` —— 吃到了多少算多少，剩下的直接作废，**不挂单**。

**📸 截图要点**：把三次的结果提示框（`已挂单` / `整单作废` / `按 IOC 作废，未挂单`）拼在一张图里 —— 一眼能看出三种有效期的区别。

> 顺手把 ① 那张 GTC 单撤掉，别留着影响后面的盘口。

## 附：常见问题

**前端打开显示「连不上后端」**
→ 终端 A 没起来，或起在了别的端口。`curl -s http://localhost:8787/config` 验一下。

**MetaMask 不弹窗 / 提示网络错误**
→ 顶栏点 `Switch to Avalanche Fuji`；或在 MetaMask 里手动切到 Fuji。

**充值后余额没变**
→ 后端要监听链上事件，等 5～10 秒。还不涨就看终端 A 有没有打印 `[chain] Deposit …`。

**成交没发生**
→ 检查 `server/.env` 里 `MARKET_MAKER=` 是**空的**。做市开着的话价差只有 1 个 tick，
你的单会被做市机器人按价格优先抢先吃掉，两个真人碰不到面。

**提现报「金库链上余额不足」**
→ 这个币在金库里的链上余额不够。用你**自己真实充值过**的币提现；跟做市账户成交赚到的币
链上没有抵押，提不出来（这是链上硬上限的设计，见 [DELIVERABLES.md](DELIVERABLES.md) 第四节 4.4）。

**提现报「提现超过链上单笔限额」**
→ 第 14 节设的限额还没还原。跑 `bash scripts/set-withdraw-limit.sh USDC 0` 改成不限。

**第 12 节做市开了之后，两个真实地址又成交不了了**
→ 这是预期的。做市照搬 Binance 报价，价差只有 1 个 tick，用户单会被做市账户按价格优先抢先吃掉。
做必做部分的成交截图时把 `MARKET_MAKER=` 改回空并重启后端。

**`node scripts/mm-compare.mjs` 报 ❌ 或连不上 Binance**
→ 先看它打印的**最大价差**：如果只是零点几个 tick、而且买卖两侧同向偏移，那是"快照时差"不是镜像坏了
（本所盘口每 `MM_INTERVAL_MS` 才镜像一次，脚本抓的是此刻的 Binance）。脚本会自动重抓，通常第 2 次就 ✅；
一直不绿就把 `MM_INTERVAL_MS` 调到 `500` 再试。
→ 如果价差很大、或档位顺序乱、或买卖方向对不上，那才是真出问题：先确认「当前委托」里没有你自己遗留的挂单。
→ `api.binance.com` 在部分网络不通，脚本用的是 `data-api.binance.vision`，如果你自己加主机记得别用前者。

**做市日志里只有 `[mm] tick#1`，后面没有新 tick 了，是不是挂了？**
→ 大概率没挂，是 **stdout 被块缓冲**了：把后端输出重定向到文件（`npm run dev > /tmp/mm.log`）时，
Node 要攒满一个缓冲区才落盘，于是日志看起来停在第一行。**在终端里直接跑（不重定向）就是实时的。**
想确认做市真的在跑，看浏览器订单簿——它每 2 秒变一次就说明在刷。
